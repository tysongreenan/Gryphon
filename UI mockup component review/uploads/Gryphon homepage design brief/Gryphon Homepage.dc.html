01 / the problem

Your agent works. The login wall doesn't care.

Every browser agent that touches a real account hits the same three walls. None of them are interesting problems. All of them kill the run.

session_expired
The cookie you pasted last Tuesday died at 3am. The run failed silently. You found out from an empty output file.
2fa_challenge
A six-digit code is sitting on your phone. Your agent has no mouth, no inbox, and no way to ask you for it.
unexpected_login_page
Mid-task, the site logs you out. The agent keeps clicking confidently into a page it can't read, then burns tokens until it times out.
paste cookies manually re-run and hope babysit the browser — none of this scales past one agent.
02 / how it works

Ask once. Recover once. Stay logged in after that.

01agent
Agent asks for a session
One MCP tool call — get_session(site). No cookie plumbing in your agent code.
02gryphon
Ready, or escalate
If a live context exists, it comes back ready. If not, Gryphon opens an escalation and pauses the agent instead of failing it.
03human
You log in, once
Slack message with the site, the reason and a screenshot. Open a signed Live View link, do the 2FA, hit resolve. Under a minute.
04agent
Every run after is warm
The authenticated context is stored per (you, site). The next get_session returns a connect URL and the agent just continues.
agent→gryphon→you→gryphon→agent, still running

03 / where it fits

A thin layer next to the tools you already run.

Gryphon composes with your stack rather than replacing any part of it. It owns exactly one thing: authenticated state, and getting it back when it breaks.

Browserbase
runs the browser
Stagehand / Playwright
drives the page
Your agent
decides what to do
Gryphon
keeps it logged in — and gets you when it can't
what gryphon is
+A session + escalation service for agents
+MCP-native, with a plain REST API underneath
+Durable per-site contexts you can revoke any time
+Human-in-the-loop as a first-class path, not a fallback hack
what gryphon is not
−An agent framework — it never decides what your agent does
−A browser automation platform — Browserbase already does that
−Site-specific actions — no "send LinkedIn message" tools
−A CAPTCHA farm — a human resolves it, and that human is you
